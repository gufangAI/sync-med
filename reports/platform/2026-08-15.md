### 二、查到 401 的真根因（今天最硬的一条）

`pan_fetch.py` 里 `_tok["exp"] = now + 3000`，注释写「tokens last ~1h」。**逼 API 自己说话**：

```
expiredAt = 2026-11-13T14:57:33+08:00  →  90 天
写死的 3000 秒 = 0.83 小时  →  相差 2602 倍
```

后果不是"多申请几次"：token 每 50 分钟换新、旧的服务端还活 90 天，**账号活 token 只增不减**，超限后 `download_info` 返回 `401 tokens number has exceeded the limit`——**报错报在业务接口上，完全不像 token 的问题**，这是我连查六轮的原因。

**平台前台 `pan123.js` 第 25 行 20 天前就写着「access_token(3个月有效 → 存20天)」。** 我今早抄了它的共享缓存思路，偏偏没抄有效期。

- 修法：一律读 API 返回的 `expiredAt`，留 1 天余量；解析不了退守 20 天
- 本机自测：**0.035 天 → 89.0 天**，拿它调 `dir_index` 回 61 个文件 ✅
- 已推：`hosonzuo/sync-med` `67c53625` · `hosonzuo/ocr-pilot` `936237da`
